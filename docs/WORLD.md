# ТЗ: мир предметов — вещи, дом, транспорт, режимы

*Версия 1.0, 2026-09-09. Расширение [SPEC.md](SPEC.md) (ТЗ v1.0) на всё, что
на экране НЕ является питомцем: вещи, с которыми он взаимодействует, дом,
транспорт, живность и игровые режимы. Карта реакций — [REACTIONS.md](REACTIONS.md),
фазы — [ROADMAP-1.0.md](ROADMAP-1.0.md).*

---

## 1. Зачем это и главный принцип

Питомец сейчас взаимодействует только с рельефом (окна, стены) и с рукой
человека. Всё остальное — «мебель мира» — отсутствует, и каждая новая
задумка («пусть уберёт за собой», «пусть будет домик», «пусть катается на
велосипеде») выглядит как отдельная фича, которую надо прибивать гвоздями
к демону.

**Главная мысль: швабра, домик, мячик, велосипед, вражеский моб и снежинка —
это одна и та же сущность.** У всех есть место в мире, вид, физика и способ
взаимодействия с питомцем и с человеком. Значит, вместо десятка частных
механик нужен один слой — **предметы (props)** — и один слой поведения —
**дела (chores/tasks)**: «дойти и сделать». Дальше любая приколюха
описывается данными и небольшим поведением, а не новой подсистемой.

Принципы, которым слой обязан подчиняться (продолжение §1 SPEC):

1. **Не мешать работе.** Предметы не перехватывают мышь вне своих
   прямоугольников, не лезут поверх активного окна, исчезают в
   полноэкранном режиме вместе с питомцем. Ничего не мигает и не пищит.
2. **Всё опционально и выключаемо.** Каждая группа (дом, транспорт,
   живность, война) включается отдельно; по умолчанию — минимум: вещи,
   которые питомец заводит сам (швабра, миска), и ничего больше.
3. **Состояние — в журнале.** Что у питомца есть, где стоит дом, какой
   транспорт открыт — события журнала, а значит синхронизация между
   устройствами и никаких конфликтов (§4.11 SPEC).
4. **Физика одна на всех.** Предметы падают, лежат на карнизах и катятся по
   той же модели, что и питомец (`core::body`, `core::physics`).
5. **Бюджет прежний.** Все предметы вместе не должны стоить дороже питомца:
   ≤ 0.5 % CPU в движении, RSS < 60 МБ. Спящий мир не тикает вовсе.
6. **Никакой экономики.** Ни денег, ни магазина, ни ежедневных заданий
   (анти-скоуп §7 SPEC). Вещи находятся, дарятся, открываются уходом.

## 2. Архитектура

### 2.1 Предмет (`core::prop`)

```rust
pub struct Prop {
    pub id: PropId,           // стабильный (из журнала) или временный
    pub kind: PropKind,       // швабра, домик, мяч, велосипед, моб…
    pub pos: Vec2,            // опорная точка, как у питомца
    pub vel: Vec2,
    pub surface: Surface,     // пол/стена/потолок — тот же якорь
    pub state: PropState,     // Idle | Held | Falling | Rolling | InUse
    pub owner: Option<Owner>, // кто держит: питомец или рука человека
}

pub struct PropClass {        // данные, не код
    pub anchor: Anchor,       // Floor | Wall | Ceiling | Corner | Free
    pub mass_kg: f32,
    pub draggable: bool,      // можно ли таскать мышью
    pub solid: bool,          // питомец может стоять сверху
    pub persist: bool,        // писать ли в журнал
    pub interact: Interact,   // что делает питомец: Use | Ride | Enter | Chase
}
```

Ключевые решения:

- **Один прямоугольник — одна хит-область.** `Scene::input_rects` уже умеет
  список; предметы добавляют свои. Перетаскивание предмета — тот же код, что
  и перетаскивание питомца (порог захвата, бросок, отмена).
- **`solid` предметы становятся рельефом**: их верхняя кромка попадает в
  `World::platforms` рядом с кромками окон, и питомец на них ходит без
  единой новой строчки в физике. Домик, коробка, стол — платформы.
- **Временные предметы** (лужа, пыль, швабра в руках) не персистятся: они
  живут в демоне и умирают со сценой.
- **Постоянные** (домик, транспорт, миска) — события журнала:
  `PropPlaced { kind, pos, surface }`, `PropMoved { id, pos }`,
  `PropTaken { id }`. Слияние — как у всего остального (G-Set + LWW по
  позиции), поэтому дом на двух устройствах стоит в одном углу.

### 2.2 Дела (`core::task`)

Питомцу нужен слой «пойти и сделать» поверх машины состояний — сейчас
каждое сценарное поведение (пробежка присутствия, прощание, уборка) написано
в демоне отдельно. Обобщаем:

```rust
pub enum Task {
    GoTo { x: f32, then: Box<Task> },
    Use { prop: PropId, secs: f32 },   // швабра, миска, лейка
    Ride { prop: PropId },             // транспорт
    Enter { prop: PropId },            // домик
    Chase { target: PropId },          // мяч, моб
    Flee { from: PropId },
    Idle,
}
```

Правила: дело **всегда прерывается** вмешательством человека (клик, захват,
меню) и никогда не пишет в журнал само по себе — журнал получает результат
(«поел из миски» = `Fed`), а не процесс. Одно дело за раз, очередь не нужна.

Выбор дела — расширение существующего `advance_timer`: наравне с «погулять»
и «поспать» появляются «сходить к миске, если голоден», «убрать лужу»,
«покататься», «загнать моба».

### 2.3 Отрисовка и порядок слоёв

Снизу вверх: тень предметов → предметы за питомцем (`z = Behind`) → тень
питомца → лужи → питомец → предметы в руках (швабра, руль) → предметы перед
питомцем (`z = Front`) → пыль → пузырь → меню. Все уже умеют деформацию и
прозрачность (фаза G6), поэтому предметы получают то же живое поведение —
мяч сминается от удара, домик покачивается, когда его ставят.

### 2.4 Где предметы берут вид

- **Процедурные** (`core::effects`): швабра, миска, мяч, коробка — рисуются
  примитивами, масштабируются под размер питомца, красятся в его цвет. Ноль
  ассетов, мгновенная итерация.
- **Пиксель-арт** (пак): домик, транспорт, мобы — новые семейства кадров в
  формате паков; внешний пак сможет их заменить.

## 3. Каталог предметов

Отмечено, что даёт вещь и чем она заслужена (никаких покупок).

### 3.1 Быт — «питомец живёт»

| Вещь | Что делает | Как появляется |
|---|---|---|
| **Швабра** | убирает лужу за собой, если его не трогают | сама, после тошноты — **сделано (H0)** |
| **Миска** | кормление через меню кладёт еду в миску, питомец идёт есть к ней и ест уже там | с первого кормления — **сделано (H2)** |
| **Лежанка** | «уложить спать» ведёт его в лежанку, и он спит В ней (передний валик рисуется поверх) | с первого «уложить спать» — **сделано (H2)**; «на второй день» оказалось хуже: вещь должна появляться из действия человека, а не из календаря |
| **Домик** | «свой угол»: встаёт в угол, перетаскивается мышью и прилипает к стене; питомец прячется туда от полноэкранного режима и выходит оттуда махать лапкой; изредка заходит сам посидеть | на третьи сутки жизни — **сделано (H3)** |
| **Полка** | вешается на стену, становится платформой | режим «стройка» |
| **Растение в горшке** | требует полива раз в пару дней; политое — цветёт и поднимает настроение | найдётся само |
| **Почтовый ящик** | сообщения между устройствами: питомец «получает письмо», когда на другом ПК его кормили | при включённом синке |

### 3.2 Игрушки — «с питомцем играют»

| Вещь | Что делает |
|---|---|
| **Мячик** | достаётся кнопкой «Мяч»; бросаешь — догоняет, берёт в лапки и приносит туда, откуда бросили; просто выданный — пинает. Физика — тот же `Body` с высоким отскоком — **сделано (H4)** |
| **Верёвочка** | тянешь мышью — цепляется и тянет в ответ |
| **Лазерная точка** | зажатая средняя кнопка = точка под курсором, гоняется как кот |
| **Воздушный шарик** | привязан к питомцу, тянет вверх: с шариком он прыгает выше и планирует |
| **Батут** | ставится на пол, отскок ×3 |
| **Качели** | вешаются между двумя окнами |

### 3.3 Транспорт — «питомец ездит»

Транспорт — предмет с профилем передвижения; питомец садится (`Task::Ride`),
и на время поездки его физика подменяется профилем. Управление не нужно:
он катается сам, но брошенный мяч или моб становятся целью.

**Сделано (H5)**: все шесть видов. Подаётся кнопкой «Прокатиться» в меню,
командой `ctl ride [вид]` или приезжает сам изредка. Скорость записана
кратностью делового шага питомца (та самая ×2/×2.5/×4 из таблицы), а не в
м/с: в «настоящих» единицах транспорт получался в разы быстрее всего
остального на экране и читался телепортацией.

| Транспорт | Профиль | Особенность |
|---|---|---|
| **Скейт / самокат** | пол, ×2 скорости, инерция, с карниза съезжает в прыжок | самый простой, первый |
| **Велосипед** | пол, ×2.5, не падает с кромок (тормозит у края) | звонок при встрече с курсором |
| **Мопед** | пол, ×4, разгон и тормоз, дымок из выхлопа | шумит только визуально |
| **Автомобиль** | пол, ×3, внутри видно питомца в окне; фары ночью | может «парковаться» у домика |
| **Вертолёт** | свободный полёт, зависание, садится на карнизы и на потолок | лопасти вращаются (уже есть кувырок кадрами) |
| **Самолёт** | свободный полёт по дуге от края до края, петли | пролетает через весь экран и уходит за край |
| **Ракета** | одноразовый запуск в потолок с огромным ускорением | пасхалка: раз в неделю |

Правило: транспорт **не телепортирует** и не ускоряет уход за питомцем —
это чистое зрелище и игра. Скорости выше пешеходных, но питомец на технике
не покидает рабочую область своего монитора.

### 3.4 Живность и «режим войны»

Отдельный **опциональный режим** (по умолчанию выключен, включается в
настройках). Смысл — не бой, а зрелище: питомец гоняет незваных гостей.

**Сделано (H6)**: пылевой комок, таракан и жук-баг. Включается
`[game] war_mode = true` в config.toml (галка в настройках — дальше),
позвать гостя руками можно всегда: `ctl mob roach`.

| Моб | Поведение | Чем кончается |
|---|---|---|
| **Пылевой комок** | катается по полу, оставляет пыль | питомец подметает шваброй |
| **Таракан** | быстро бегает по кромкам, прячется под окна | питомец гоняется, моб убегает за край |
| **Жук-баг** | сидит на заголовке окна, «портит» его (визуально) | питомец сбрасывает его вниз |
| **Робот-пылесос** | ездит по полу, мешает ходить, может «увезти» питомца | питомец запрыгивает сверху и катается |
| **Тень-двойник** | появляется ночью, повторяет движения питомца | исчезает, если посветить (лазерная точка) |

Жёсткие ограничения режима:

- **Никакой смерти и урона.** Проигранная стычка = настроение вниз и
  «испугался», не более. Здоровье не трогается.
- Мобы появляются **редко** (раз в несколько часов) и живут минуты.
- Мобы никогда не перекрывают активное окно и не ловят мышь.
- Всё, что происходит в режиме войны, **не пишется в журнал ухода** — это
  игра, а не история питомца. В журнал идёт только настроение (`Played`).

### 3.5 Сезонное и редкое (пасхалки)

Снег зимой (лепит снеговика), листья осенью, дождь за «окном» домика, ёлка
в декабре, шляпы и аксессуары как награды за уход (коллекция в сундуке),
день рождения (уже есть), «гость» — питомец с другого устройства приходит в
гости при включённом синке.

## 4. Режимы

| Режим | Что включает | По умолчанию |
|---|---|---|
| **Обычный** | быт: швабра, миска, лежанка | вкл |
| **Стройка** | курсор ставит и двигает предметы; сетка привязки к углам, стенам, карнизам; питомец с интересом ходит смотреть | выкл, включается на время |
| **Игра** | игрушки и транспорт | вкл (по мере появления вещей) |
| **Война** | мобы и стычки | выкл |
| **Тихий** | никаких предметов, только питомец (для важной работы) | выкл |

Переключение — в настройках и в радиальном меню (второе кольцо по
удержанию ПКМ: «режимы»).

## 5. План по фазам

| Фаза | Содержание | Критерий готовности |
|---|---|---|
| **H0** | Первый предмет по образцу: швабра и уборка лужи; плавное угасание лужи и зелени | **сделано** |
| **H1** | `core::prop` + `core::task`: сущность предмета, якоря, физика, перетаскивание мышью, `solid` как платформа; перенос швабры на новый слой | **сделано** |
| **H2** | Быт: миска (голодный идёт есть), лежанка (спит в ней) — первые постоянные предметы в журнале | **сделано** |
| **H3** | Домик: привязка к углу/стене, перетаскивание, вход/выход, прячется туда при полноэкранном режиме | **сделано** (арт процедурный, пиксель-арт пака — позже) |
| **H4** | Игрушки: мяч (кинуть — принесёт), лазерная точка, шарик | **мяч сделан**; точка и шарик — дальше |
| **H5** | Транспорт: профиль передвижения, скейт → велосипед → мопед → автомобиль; полёт (вертолёт, самолёт) | **сделано** (все шесть, арт процедурный) |
| **H6** | Режим войны: мобы, стычки, режимы в настройках и меню | **сделано** (три гостя; переключатель пока в config.toml, не в UI) |
| **H7** | Сезонное, аксессуары, «гость» с другого устройства | — |

H1 и H2 — фундамент, без них остальное снова превратится в набор костылей.
Порядок H3→H5 можно менять по желанию; H6 последний, потому что опирается
на всё.

## 6. Риски и чего не делаем

- **Загромождение экрана.** Правило: одновременно на экране не больше
  **пяти** предметов плюс питомец; остальное живёт «в домике». Режим
  «тихий» убирает всё одним переключателем.
- **Съезжание в игру.** Транспорт и мобы не должны становиться обязательными:
  уход за питомцем работает без них полностью.
- **Бюджет.** Каждый предмет — это спрайт и тик; при пяти предметах тик
  остаётся ≤ 0.5 % CPU, иначе фича режется.
- **Не делаем**: экономику и магазины, PvP, урон и смерть, обязательные
  ежедневные активности, предметы, перехватывающие ввод вне своей области.

## 7. Открытые вопросы

1. Домик: одна комната «изнутри» (питомец виден в окошке) или просто
   закрытая коробка, куда он заходит?
2. Транспорт открывается уходом (награда) или доступен сразу в режиме игры?
3. Мобы: свои спрайты или «тени» существующих (дешевле, но беднее)?
4. Нужен ли режим «стройка» отдельной кнопкой, или достаточно того, что
   предметы всегда перетаскиваются мышью?
5. Синхронизация предметов: позиция домика — общая на все устройства или
   своя для каждого экрана (разные разрешения)? Скорее своя, с общим
   фактом владения.
