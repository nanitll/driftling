# Аудит Driftling — GAP-лист до «продаваемого» качества

Дата: 2026-08-12. Осмотрен весь код (~3.7 kLOC), docs/TZ.md, CI, манифесты. Статус кода: выполнены M0 + M0.5, всё остальное (M1–M7) отсутствует. Репозиторий **не под git** — при заявленном в ТЗ §8 «публичный с первого коммита».

---

## Технический долг и хрупкость

### Платформа / Wayland

1. **Один выход, мультимонитор отсутствует.** `crates/platform/src/wayland.rs:79-83` — `TODO(M3)`, surface создаётся с `output=None`; `OutputHandler` — пустые заглушки (`wayland.rs:360-364`). Питомец живёт на «каком-то» выходе, который выбрал композитор.
2. **Хотплаг выхода / рестарт композитора = смерть демона без восстановления.** `LayerShellHandler::closed` (`wayland.rs:368-373`) доставляет `Shutdown` и глушит цикл; обрыв Wayland-соединения роняет `event_loop.run` с ошибкой. Ни реконнекта, ни пересоздания слоя, ни `Restart=` в autostart (`settings/src/main.rs:111-119` — голый .desktop). Отключил монитор у ноутбука / перелогинился — питомец исчез навсегда до ручного запуска.
3. **30fps-таймер молотит всегда** (`wayland.rs:62`, `123-131`): тикает и рисует полный кадр даже когда питомец спит, стоит в idle или вовсе dismissed (пустая сцена всё равно проходит через `tick_and_draw`). ТЗ §7 требует «в покое — таймер ≥1 с». Плюс **нет dirty-check**: `compose()` (`wayland.rs:249-255`) заливает и передаёт полный fullscreen-буфер с `damage_buffer` на весь экран (`wayland.rs:227`) каждые 33 мс. На 4K это ~33 МБ ARGB fill + full damage 30 раз/с — бюджеты «CPU <0.5%, RSS <60 МБ» (ТЗ §7) с высокой вероятностью нарушены; damage-only из ТЗ §4 не реализован.
4. **Fullscreen-буфер на весь выход** вместо маленькой поверхности/субповерхности под спрайт — двойная буферизация SlotPool на 4K съест десятки МБ RSS. ТЗ §4 п.3 описывал субповерхности — их нет.
5. **Drag ломается при быстром движении мыши.** Input region = только прямоугольник питомца, обновляется раз в кадр (`daemon.rs:241`, `wayland.rs:213-224`). Курсор выскочил из rect'а между кадрами → `Leave`, Motion/Release больше не приходят (обрабатываются только Enter/Motion/Press/Release LEFT, `wayland.rs:461-472`; `Leave` игнорируется) → питомец завис в `Dragged` навечно, физика выключена (`pet.rs:119-121`). Во время drag регион надо расширять на весь экран либо обрабатывать Leave как Release.
6. **Только целочисленный scale.** `scale_factor_changed` (`wayland.rs:301-311`) — при дробном масштабировании KDE (125–150%, типичный кейс целевой платформы P0) спрайт будет мылиться/скакать; `wp_fractional_scale`/`viewporter` не используются.
7. **Exclusive-зоны панелей игнорируются** (`exclusive_zone(-1)`, `wayland.rs:85`; `World::ground_y` = низ экрана, `pet.rs:36-38`): питомец ходит *поверх* панели KDE, а не по её верхней кромке. ТЗ §3.1 прямо требует «учитывая exclusive-зоны панелей».
8. **Layer::Overlay поверх fullscreen**: питомец гуляет поверх фильма/игры. Автоскрытие при fullscreen (ТЗ §3.1) отсутствует.
9. **ПКМ и средняя кнопка молча съедаются** над питомцем (input region ловит, событие отбрасывается, `wayland.rs:472`) — и контекстного меню нет, и клик «сквозь» не проходит.

### IPC

10. **Нет версии протокола.** `ipc/src/lib.rs:12-43` — externally-tagged serde-enum по JSON без version-поля и без handshake. Старый демон + новый клиент = `Error("bad request: unknown variant …")` (уже кусалось дважды). Нужно: поле версии в первом сообщении либо конверт `{v, req}` + политика совместимости.
11. **Сервер умирает от отвалившегося клиента.** `serve()` (`lib.rs:105`, `:98`) пробрасывает ошибку `write_resp` через `?` → EPIPE (клиент закрылся, не дождавшись ответа — например, убитый `ctl`) завершает `serve()` с Err, IPC-поток умирает (`daemon.rs:50-52` лишь логирует), демон живёт дальше **без канала управления**: ни quit, ни настройки. Тихая деградация худшего сорта.
12. **Один блокирующий клиент вешает весь IPC.** `serve()` однопоточный, `read_line` без таймаута (`lib.rs:85-92`): процесс, открывший сокет и молчащий, блокирует все остальные запросы навсегда — настройки покажут «демон не запущен».
13. **Fallback пути сокета в `/tmp`** (`lib.rs:46-49`): без `XDG_RUNTIME_DIR` сокет ложится в мир-писуемый каталог с предсказуемым именем — squatting/DoS от другого пользователя. Плюс проверка «протухшести» через connect (`lib.rs:76-78`) — TOCTOU-гонка; единственная защита от второго инстанса — фейл bind.
14. **Quit завершает сервер даже при ошибке обработчика** (`lib.rs:95-100`): `quit` определяется по запросу, а не по успеху ответа.

### Состояние, краши, логи

15. **pet.json без версии схемы** (`attributes.rs:74-88`): эволюция формата — только через serde-default; переименование поля молча потеряет данные. Битый файл → дефолтный рекорд (`daemon.rs:81-85`), и первый же `SetAttributes` **перезапишет** битый (возможно восстановимый) файл. Бэкап-копии нет.
16. **pet.json = один питомец** по построению (одна запись, без id) — мультипитомцы M4 и журнал M2 потребуют миграции формата, которая не заложена.
17. **Состояние «dismissed» не переживает рестарт**: первая геометрия всегда призывает (`daemon.rs:258-264`). Убрал питомца → перелогинился → он снова тут.
18. **Нет panic hook / крашрепорта.** Паника в tick → процесс умирает молча; в настройках паника поллера отравляет Mutex, и все `lock().unwrap()` (по всему `settings/src/main.rs`) уронят UI каскадом.
19. **Логи — env_logger в stderr** (`main.rs:46`, `settings/main.rs:1181`). Под autostart через .desktop stderr уходит в никуда/в общий journal сессии без идентификации юнита. ТЗ §7: journald + `ctl doctor` — нет ни того, ни другого. Диагностика «почему питомец не появился» невозможна.
20. **Нет обработки SIGTERM/SIGINT** — при выключении сессии демон убивается без шанса на финальную запись (для M2-журнала станет критично).

### Симуляция / рендер

21. **Зеркалирование подменяет анимацию.** `SpriteSet::frame` игнорирует `facing` (`sprite.rs:39` — `let _ = facing`), зеркалит рендер попиксельно (`wayland.rs:284-288`). Для симметричного блоба терпимо, но: фаза шага ног инвертируется при развороте, блик глаза уезжает не в ту сторону, «Zz» спящего прыгает на другую сторону; для реальных асимметричных паков (M4) нужны отдельные left/right-кадры или анкеры — формата под это нет (в `Frame` нет hotspot/anchor).
22. **Поллинг настроек — вечный поток без остановки и backoff** (`settings/main.rs:233-239`): раз в секунду коннект к сокету, даже когда демон лежит и окно свернуто; поток не джойнится при выходе.
23. **`ctl reload` — заглушка**: `Config` — пустая структура (`config.rs:12-15`), reload читает файл и выбрасывает (`daemon.rs:194-202`). Команда обманывает пользователя.
24. **Клик = захват.** `PointerEvent::Press` сразу `Dragged` (`pet.rs:163-170`); «клик-реакции» из критерия приёмки M0 фактически не реализованы (клик без движения = бросок с нулевой высоты).
25. **Портрет в настройках рисуется своим `placeholder()`** (`settings/main.rs:591-609`), а не спрайтами демона — при появлении паков (M4) портрет разойдётся с реальным питомцем. ТЗ §3.3: «портрет из его настоящих спрайтов».

### Тесты / CI / сборка

26. **Тесты мутируют глобальные env vars**: `daemon.rs:378-381` (`XDG_DATA_HOME`), `ipc/lib.rs:125-127` (`XDG_RUNTIME_DIR`) — гонки при параллельном прогоне тестов в одном процессе; `std::env::set_var` становится `unsafe` в edition 2024 — переход на новую edition сломает сборку. Нужен DI пути (как уже сделано для autostart: `set_autostart_at`).
27. **CI не собирает артефакты**: нет release-сборки, deb/AppImage (ТЗ §8), нет smoke-теста в headless-композиторе (ТЗ §8), нет MSRV, нет `cargo-deny`/`cargo audit` для лицензий/уязвимостей.
28. **Экранирование Exec не делается** (`settings/main.rs:111-119`): путь с пробелом ломает .desktop; autostart-файл KDE-специфичен (`X-KDE-autostart-after=panel`) — на sway/river (целевая P0-платформа!) XDG autostart вообще не работает без спец-демона, systemd user unit не предложен.
29. **`repository = "https://github.com/driftling/driftling"`** в Cargo.toml — репозитория не существует, каталог даже не git.

### i18n

30. **Русский захардкожен везде**: UI настроек целиком, вывод CLI (`main.rs:79-88`), логи, ошибки IPC («демон не ответил вовремя»), дефолтное имя «Дрифтлинг» (`attributes.rs:84`). Fluent/gettext (ТЗ §7 «en+ru с первого релиза») не заложены — чем позже, тем дороже: строки размазаны по 5 crates. Англоязычный пользователь (основная опенсорс-аудитория) не поймёт ни CLI, ни настройки.

## Пробелы до «продукта» (что заметит платящий пользователь в первый час)

1. **Нет тамагочи.** Голод/энергия/настроение, кормление, рост, журнал — ничего (journal.rs — 35 строк типов-заготовок). Продукт сейчас — «фиолетовый блоб ходит по низу экрана». Ядро ценностного предложения (M2) отсутствует.
2. **Плейсхолдер-арт.** Процедурный эллипс с глазами (`sprite.rs`). Продаёт питомца — характер и арт; нужен художник/стиль-гайд (открытый вопрос №2 ТЗ так и не решён).
3. **Нет контекстного меню** (ПКМ: покормить/поиграть/статус/настройки — ТЗ §3.3). Единственные взаимодействия — таскание и CLI.
4. **Нет трея** (StatusNotifierItem): закрыл настройки — приложение «исчезло», нового способа добраться до него пользователь не знает.
5. **Настройки не умеют ЗАПУСКАТЬ демона.** Есть кнопка «Остановить демона» (`settings/main.rs:994`), но при «Демон не запущен» нет кнопки «Запустить» — тупик для пользователя после первого краша.
6. **Нет анимаций призыва/ухода**: summon телепортирует тушку в воздух (`daemon.rs:127`), dismiss мгновенно стирает. Для продукта с фирменным UX «перебегает между устройствами» — заметная дырка.
7. **Нет редактирования имени питомца** (rename есть только как тип `CareKind::Renamed` в заготовке журнала).
8. **Один питомец**, ни окон-рельефа (M1), ни синка (M3), ни паков (M4) — обещания README не совпадают с бинарём.
9. **Onboarding отсутствует**: ни первого запуска (яйцо? приветствие?), ни объяснения «что это и как убрать», ни fullscreen-режима вежливости (питомец топчется по видео).
10. **Установка/удаление**: нет пакетов (deb/AppImage/Flatpak), нет `make install`, uninstall-истории нет — autostart-файл, pet.json, config.toml остаются навсегда.
11. **Крашнулся — молчание**: питомец пропал, никакого «упс, вернуть питомца?» при следующем входе, логов пользователь не найдёт.
12. **GNOME/X11-пользователь** получает голую ошибку `zwlr_layer_shell_v1 недоступен` на русском в невидимый stderr — вместо внятного «ваш композитор не поддерживается, вот список».
13. **README**: статус «проектирование» (устарел — код есть), нет инструкции сборки, нет гифки, нет CONTRIBUTING/CoC/шаблонов issue (ТЗ §8).

Бюджеты ТЗ §7 сейчас нарушаются самой архитектурой рендера (fullscreen-буфер, 30fps всегда) — это надо чинить до, а не после M1, иначе M1 построится на неверном фундаменте.
