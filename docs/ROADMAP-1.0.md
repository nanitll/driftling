# Driftling: дорожная карта до продукта 1.0

*Составлена 2026-08-12 на базе [аудита кода](AUDIT-2026-08.md) (≈40 конкретных проблем с file:line) и [проверенного справочника по дистрибуции](SHIPPING.md). Стратегическое видение и вехи M0–M7 — в [TZ.md](TZ.md); этот документ — операционный план, как из текущего прототипа сделать вещь, которую не стыдно продавать.*

## 0. Определение «законченного продукта» (Definition of Done 1.0)

**1.0 — это Linux-релиз.** Windows/macOS (M5 ТЗ) сознательно выносятся в 2.0: иначе 1.0 недостижим. Продукт готов, когда незнакомый человек:

1. Ставит Driftling за 2 минуты из AppImage/deb/AUR и получает **онбординг**: на экране появляется яйцо, вылупляется питомец, три ненавязчивые подсказки (покормить/потаскать/где настройки).
2. Видит **настоящий арт с характером**, а не процедурный блоб; иконка приложения нормальная везде.
3. Получает **полный тамагочи-цикл**: голод/настроение/энергия, кормление через меню ПКМ, рост яйцо→взрослый с ветвлением от качества ухода, реакции (встречает при входе, скучает, радуется).
4. Питомец **ходит по окнам** на KDE/wlroots/X11; на GNOME — честная деградация с внятным объяснением; не топчется поверх фильма; уважает панель как пол; живёт на нескольких мониторах; не мылится при дробном масштабе.
5. Может включить **синк**: свой сервер (один бинарь/Docker) или папка Syncthing/Nextcloud; питомец «перебегает» между устройствами.
6. **Ничего не разваливается**: рестарт композитора/перелогин/kill -9 — питомец возвращается сам; краш не теряет прогресс; после недели непрерывной работы CPU ≈ 0%, RSS < 60 МБ.
7. Работает на **английском и русском**; удаляется бесследно; `driftling ctl doctor` объясняет любую проблему.

## 1. Текущее состояние (честно)

Готовы M0 (питомец ходит/падает/таскается, Wayland-оверлей) и M0.5 (дизайн-система настроек, характеристики у питомца, дебаг-панель). Это ~15% продукта. Аудит: 30 позиций техдолга + 13 продуктовых дыр; ключевые системные проблемы — **(а)** демон не переживает смерть окружения (рестарт композитора = исчез навсегда), **(б)** рендер жрёт бюджет архитектурно (fullscreen-буфер 30 fps всегда, на 4K ~33 МБ заливки 30 раз/с), **(в)** IPC без версии и падает от отвалившегося клиента, **(г)** русский захардкожен в 5 крейтах, **(д)** тамагочи — 35 строк типов-заготовок.

## 3. Порядок, параллельность, объёмы

```
F1 ──────────────────────────────────────────────► (фон: релизы 0.x после каждой фазы)
A ──► B ──────────► D ──► E ──► полировка ──► 1.0
      C (арт, параллельно B; блокирует только финал B)
```

Грубая оценка объёма (в «рабочих сессиях» такой же интенсивности, как M0/M0.5, каждая = день):

| Фаза | Сессий | Комментарий |
|---|---|---|
| A | 2–3 | много мелких S/M-задач, хорошо параллелится агентами |
| B | 3–4 | ядро; журнал и баланс — самое думательное |
