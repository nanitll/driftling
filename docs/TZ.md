# ТЗ: Driftling — десктопный тамагочи

*Версия 0.2, 2026-08-07. Название **Driftling** утверждено 07.08.2026 (проверка коллизий — RESEARCH.md; ник GitHub, crates.io и .app/.dev/.io свободны на эту дату). Обзор конкурентов и первоисточники — в [RESEARCH.md](RESEARCH.md).*

## 1. Видение

Опенсорс-питомец, который **живёт на экране**: ходит по нижней кромке, забирается на окна и сидит на заголовках, падает, когда окно двигают, — и при этом является **настоящим тамагочи**: у него есть голод, настроение, энергия, он растёт и меняется в зависимости от ухода.

Вторая опора видения — **один питомец на всех устройствах**: состояние синхронизируется через свой сервер (VPS или домашний ПК) либо общий хост, питомец «перебегает» на то устройство, за которым сидит пользователь.

Позиционирование (по результатам обзора рынка): все существующие проекты — либо «ходят по окнам, но без геймплея» (семейство shimeji), либо «полноценный тамагочи, но Windows-only и не трогает окна» (VPet-Simulator, 6.6k★). Проекта, который совмещает обе половины и при этом **Linux/Wayland-first**, не существует. Мультиустройство — тоже пустая ниша: максимум, что есть у кого-либо, — синк файла сейва (VPet через Steam Cloud, с документированными потерями сейвов) или «перенос» питомца между устройствами (Tamagotchi On); живого присутствия одного питомца на нескольких устройствах нет ни у кого (подробно — RESEARCH.md, раздел «Мультиустройство»).

Принципы:

1. **Питомец, а не игра.** Не отвлекает: потребности выражаются позой и анимацией, не попапами; никаких звуков по умолчанию; взаимодействие всегда инициирует пользователь. Idle-механики «зайди проверь таймер» — запрещены.
2. **Wayland — первый класс, а не порт.** Большинство конкурентов умерли или деградировали именно на переходе X11→Wayland. Мы проектируем от Wayland, X11 получаем «в подарок».
3. **Крошечный след.** Это фоновая программа на 8+ часов в день. Бюджеты (§7) — жёсткие требования, не пожелания.
4. **Контент отделён от движка.** Спрайт-паки — данные, загружаемые пользователем; в репозитории только собственный арт под свободной лицензией.
5. **Local-first, сервер опционален.** Всё работает без сети; синхронизация — надстройка, которую пользователь включает одной настройкой адреса (модель atuin). Сервер свободный и лёгкий (один бинарь + SQLite), не повторяем ошибку Joplin с несвободным сервером.

## 2. Целевые платформы и приоритеты

| Приоритет | Платформа | Оверлей | Геометрия окон | Режим |
|---|---|---|---|---|
| P0 | Linux Wayland: **KDE Plasma** | wlr-layer-shell | KWin-скрипт → D-Bus | полный |
| P0 | Linux Wayland: **wlroots** (sway, river и др.) | wlr-layer-shell | sway IPC; иначе только экран | полный / базовый |
| P1 | Linux **X11** (все DE) | override-redirect + ARGB + Shape | EWMH (`_NET_CLIENT_LIST_STACKING` + геометрия) | полный |
| P1 | Linux Wayland: **Hyprland** | wlr-layer-shell (см. риск §10.3) | Hyprland IPC (`clients -j`) | полный |
| P2 | Linux Wayland: **GNOME** | нет layer-shell → XWayland-фолбэк | собственное расширение Shell (образец — window-calls) | деградированный / через расширение |
| P2 | Linux Wayland: **COSMIC** | layer-shell | `zcosmic_toplevel_*` (единственный протокол с событием geometry) | полный |
| P3 | Windows 10/11 | WS_EX_LAYERED/TRANSPARENT | Win32 EnumWindows | полный |
| P3 | macOS | NSWindow ignoresMouseEvents | Accessibility API (требует разрешения) | полный |

«Базовый режим» = питомец ходит только по кромкам экрана/панелей; «полный» = окна становятся рельефом.

## 3. Функциональные требования

### 3.1 Питомец на экране (движение и физика)

- Ходьба по нижней кромке экрана (учитывая exclusive-зоны панелей), бег, сидение, сон, idle-анимации.
- Гравитация: питомец падает с кромок; падение с высоты — анимация приземления/оглушения.
- Лазание по боковым кромкам экрана, свисание с верхней.
- **Окна как рельеф** (полный режим): верхняя кромка каждого окна — платформа (модель XPenguins/shimeji); питомец ходит по заголовкам, сидит на них, перепрыгивает между окнами; при перемещении/закрытии окна — падает; учитывается z-порядок (питомец «за» окном не рисуется поверх — минимум: работаем только по верхним кромкам видимых окон из stacking order).
- Drag & drop мышью с физикой броска (инерция, отскок).
- Мультимонитор: единое глобальное пространство координат (xdg-output), питомец свободно переходит между экранами; опция привязки к одному экрану.
- Автоскрытие при полноэкранном приложении (прецедент — wayland-vpets) и в режиме «не беспокоить».

### 3.2 Тамагочи-механики

Модель — гибрид Tamagotchi P1 (стадии, ошибки ухода) и VPet-Simulator (стат-интерлок, без пермасмерти). Все числа — стартовые значения для балансировки, выносятся в конфиг.

**Статы (0–100):**

| Стат | Скорость деградации (актив) | Что восполняет | Следствие нуля |
|---|---|---|---|
| Сытость | 100→0 за ~8 ч | еда из меню/инвентаря | здоровье ↓, грустные позы |
| Энергия | 100→0 за ~10 ч | сон (сам ложится; можно уложить) | засыпает где стоит |
| Настроение | 100→0 за ~12 ч | игра, поглаживание, прогулки по окнам | вялость, здоровье ↓ |
| Чистота (v2, опц.) | медленно | «помыть» | настроение ↓ |
| Здоровье (скрытый) | производный | само при хорошем уходе | болезнь |

- Кормление: половина эффекта сразу, половина — постепенно (анти-перекорм, приём VPet). Еда обычная и «вкусняшки» (настроение↑, но злоупотребление → болезнь — приём P1).
- Потребность «всплывает» не чаще раза в 1–3 часа; интервал логики конфигурируем (медленнее тик = менее требовательный питомец).
- **Оффлайн-прогресс с полом**: при запуске статы пересчитываются за прошедшее время, но не ниже 20% — питомец встречает «голодным и сонным», никогда мёртвым (валидировано самим Bandai: в My Tamagotchi Forever смерти нет).
- **Смерти по умолчанию нет.** Запущенность → болезнь → питомец «обижается и уходит» (временно). Опциональный hardcore-режим с классическими ставками — для желающих.
- **Рост**: яйцо → малыш → ребёнок → подросток → взрослый. Реальное время (1 день = 1 «год») + счётчик ошибок ухода на переходах определяет ветку взрослой формы (легальная и понятная система P1: «кем он стал — результат твоей заботы»).
- Персистентность: **журнал событий ухода** (append-only, §3.5) + кэш-снапшот в `~/.local/share/driftling/`, атомарная запись; конфиг в `~/.config/driftling/config.toml`. Журнал — не деталь синка, а базовый формат состояния с M2: статы всегда выводятся из журнала детерминированно.

### 3.3 Взаимодействие

- Клик по питомцу — реакция; зажать — погладить; drag — перенести/бросить.
- Контекстное меню (ПКМ): покормить, поиграть, уложить спать, статус, настройки.
- **Приложение настроек с GUI** (`driftling settings` / бинарь `driftling-settings`, запускается из трея, контекстного меню и CLI): статус и статы питомца, кнопки призвать/убрать/остановить, все параметры поведения и тамагочи (редактирует `config.toml`), тумблер автозапуска, позже — выбор пака (M4) и синк (M3: адрес сервера, имя устройства, режим присутствия). Стек — egui/eframe (чистый Rust, MIT/Apache, кроссплатформенно). Окно — отдельный короткоживущий процесс: бюджеты §7 на него не распространяются, демон остаётся крошечным. Изменения применяются живым демоном без перезапуска (IPC `Reload`).
- Трей-иконка (StatusNotifierItem) + CLI `driftling ctl …` (summon/dismiss/feed/status/config) через unix-socket.
- Реакции на события системы: приветствие при логине, «скучал» после простоя, поглядывает на курсор (KWin отдаёт позицию курсора).

### 3.4 Контент и паки

- **Нативный формат пака**: каталог/архив со spritesheet (PNG) + манифест TOML/JSON (кадры, анимации, хитбоксы, метаданные, **обязательное поле лицензии и автора**).
- **Импорт shimeji-паков** (сотни готовых на shimejis.xyz/DeviantArt): офлайн-конвертер по модели wl_shimeji (`driftling import <zip>`), а не рантайм-исполнение. Условия `Condition` (JS-выражения) транслируются в наш формат при импорте; экзотика — по мере запросов. Поддержать и оригинальную японскую схему тегов (`<マスコット>` и др.) — известные грабли: конвертеры, понимающие только английскую схему Shimeji-ee, молча теряют паки.
- Мультипитомцы (v2): несколько одновременно, у каждого своё состояние. Размножение — **выключено по умолчанию** (проверено на опыте: у wl_shimeji дефолтный BREEDING за минуты заполняет экран).

### 3.5 Мультиустройство: селфхост и общий хост (ключевая механика)

**Цель:** один и тот же питомец на всех устройствах пользователя — рабочий ПК, ноутбук, домашний ПК. Покормил на работе — дома он сытый.

**Три режима работы** (переключение — одна настройка `sync.address`, модель atuin):

1. **Standalone** (по умолчанию) — без сети, как раньше.
2. **Свой сервер** — `driftling-server` на VPS, домашнем ПК или в LAN: один статический Rust-бинарь (+ официальный Docker-образ и compose-пример), SQLite (WAL), TLS через reverse-proxy (Caddy/nginx), конфиг из одного файла. Ровно то, что selfhost-сообщество считает эталоном (atuin/PocketBase/vaultwarden).
3. **Общий хост** — официальный инстанс того же серверного кода: multi-tenant, аккаунты по токенам, rate limiting. Регистрация без e-mail (генерируемый ключ аккаунта).

**Модель данных — журнал событий, а не файл сейва.** Источник истины — append-only журнал событий ухода (кормление, поглаживание, сон, переименование…). Статы не синхронизируются вообще: они — детерминированная функция (журнал, время). Синхронизация = объединение множеств событий с уникальными ID — это G-Set CRDT, слияние коммутативно/идемпотентно, **конфликты невозможны по построению**. Пользователь никогда не видит диалог «выбери сейв: локальный или облачный» (анти-прецедент: Steam Cloud у VPet — автору пришлось строить защитные бэкапы, сообщество написало сторонний синк-сервер). Полноценные CRDT-библиотеки (Automerge/Yjs) не нужны — наш случай проще. Поле-подобные значения (имя питомца) — LWW по метке времени на уровне поля.

**Время и часы.** Метки событий — гибридные логические часы (HLC): `ISO-millis + счётчик + device-id`, лексикографически сортируемые (формат Actual Budget — референсная реализация jlongster/crdt-example-app). Защита от кривых часов: события из будущего дальше ~60 с отвергаются с понятной ошибкой «проверь часы на устройстве X»; вся decay-математика клампится (`max(0, Δt)`). **Анти-чит не строим**: перевод часов — «твоя игра» (прецедент Animal Crossing: только мягкие диегетические последствия). На общем хосте авторитетно серверное время.

**Дешёвый уровень — синк через папку.** Для тех, у кого уже есть Syncthing/Nextcloud/WebDAV: журнал пишется как **один append-only файл на устройство** (single-writer → конфликты файлового синка недостижимы по построению — паттерн tonsky «Local, first, forever»), записи самоограниченные с чексуммами (устойчивость к «рваному хвосту» при снапшоте синкером), чужие файлы устройств читаются как read-only. Живую SQLite-базу файлами не синкаем никогда (sqlite.org/howtocorrupt). Этот уровень даёт состояние без живого присутствия.

**Присутствие: питомец один.** Синк состояния и присутствие — раздельные механики:

- По умолчанию питомец **виден на одном устройстве** — том, где последним был ввод пользователя. Владение — lease с heartbeat через сервер; новое устройство забирает питомца (newest-wins, модель Steam «игра запущена на другом компьютере», но без драмы: с анимацией «убежал за край экрана» на старом устройстве и «прибежал» на новом — это наш фирменный UX).
- При потере сети lease истекает, но устройство продолжает показывать питомца и заботиться локально; журналы сольются при переподключении. Двойное кормление в партиции — милый сбой, а не катастрофа.
- Опция «зеркало»: питомец виден на всех устройствах одновременно (кому важнее вид, чем целостность иллюзии).

**Приватность.** Данные нечувствительны (статы питомца), но на общем хосте — опция **E2E-шифрования журнала** (модель atuin: PASETO v4.local, ключ на клиенте, сервер видит только блобы). Компромисс честно документируем: с E2E сервер — слепое хранилище + брокер присутствия, серверная симуляция и будущие соц-фичи («сходить в гости», модель VPet-мультиплеера) доступны только без E2E. На своём сервере E2E по желанию.

**Протокол** — простой, версионированный, документированный (HTTP push/pull журнала + WebSocket для присутствия; merkle-структура по HLC-меткам для дешёвого поиска точки расхождения — приём Actual Budget). Цель — чтобы сторонний сервер можно было реализовать независимо (урок vaultwarden: маленький совместимый сервер — лучшее, что случалось с экосистемой Bitwarden).

### 3.6 «Внутри окон» (v3, экспериментально)

Wayland/X11 не позволяют рисовать «внутри» чужого окна безопасным способом (X11-reparenting ломает приложения — подтверждено исследованием). Реалистичные пути:

- **Браузерное расширение** (модель oneko.js) + native-messaging-мост к демону: питомец «запрыгивает» в окно браузера и бегает по странице, состояние общее с десктопным.
- Визуальная имитация на X11: оверлей, обрезанный по контент-ректу целевого окна (Shape bounding) — выглядит как «внутри», окно не трогаем.
- Терминальный мини-режим (`driftling tty`) — ASCII-версия питомца с теми же статами.

### 3.7 Мобильные приложения и вебапп (v4, последняя крупная доработка)

Питомец приходит на телефон и в браузер: тот же журнал, тот же сервер, полный уход с любого устройства. Присутствие расширяется естественно — отошёл от ПК, питомец «перебежал» в телефон.

- **Android** (первым): полноценное воплощение возможно — Android разрешает оверлей поверх других приложений (`SYSTEM_ALERT_WINDOW`, прецедент — мобильные версии Shimeji), плюс «дешёвые» формы: виджет домашнего экрана и живые обои. Уведомления о потребностях — сдержанные и по умолчанию выключенные (принцип §1.1 действует и тут).
- **iOS**: оверлеев нет — питомец живёт в приложении + виджеты/Live Activities («питомец на островке»).
- **Вебапп**, две роли:
  1. **«Комната» питомца** — страница, которую отдаёт сам `driftling-server` (встроенный веб-UI, модель PocketBase): посмотреть, покормить, статы — из любого браузера без установки.
  2. Клиентская логика в браузере — **тот же `core` на WASM**: статы/журнал/слияние считаются одним и тем же кодом на всех платформах, никакой второй реализации правил.
- **Техническое требование, действующее с M2**: crate `core` не имеет платформозависимостей и собирается в `wasm32` (проверяется в CI с M2); мобильные привязки — через uniffi. Это дешёвая страховка сейчас против дорогого переписывания потом.

## 4. Архитектура

```
driftling (один бинарь: демон + CLI-подкоманды)
│
├── core/            — чистая логика, ноль платформозависимостей;
│                      собирается в wasm32 (CI-проверка с M2) — задел под
│                      веб/мобильные клиенты M7 (uniffi-биндинги)
│   ├── journal      — журнал событий: HLC-метки, запись/слияние (G-Set),
│   │                  снапшоты/компакция — единый формат для диска и синка
│   ├── sim          — статы и рост как детерминированный fold по журналу,
│   │                  оффлайн-пересчёт
│   ├── behavior     — стейт-машина поведения (walk/climb/fall/sit/sleep/…)
│   ├── physics      — гравитация, платформы, броски
│   └── packs        — нативный формат + конвертер shimeji
│
├── platform/        — trait Overlay (создание поверхностей, input-region, кадры)
│   ├── wayland      — smithay-client-toolkit: layer-shell overlay на каждый
│   │                  выход, wl_subsurface на питомца, пустой/точечный
│   │                  input region, xdg-output для глобальных координат
│   └── x11          — x11rb: override-redirect ARGB + Shape(Input) + EWMH ABOVE
│
├── worldsense/      — trait WindowGeometry (рельеф из окон)
│   ├── kwin         — свой KWin-скрипт (загрузка через org.kde.kwin.Scripting
│   │                  /Scripting D-Bus), пуш frameGeometry/stackingOrder/cursor
│   ├── hyprland     — сокеты IPC (запросы + событийный поток)
│   ├── sway         — i3-IPC get_tree + подписка window
│   ├── x11          — EWMH _NET_CLIENT_LIST_STACKING + ConfigureNotify
│   ├── gnome        — своё расширение Shell (D-Bus, по образцу window-calls)
│   └── null         — нет данных → базовый режим (только кромки экрана)
│
├── settings/        — GUI настроек (eframe/egui), отдельный бинарь
│                      driftling-settings: config.toml + IPC к демону
├── render/          — softbuffer (CPU), damage-only, кадры 8–15 fps
├── sync/            — клиент синка: HTTP push/pull журнала, WebSocket-присутствие
│                      (lease/heartbeat), бэкенд «папка» (single-writer файлы)
├── server/          — driftling-server: axum + SQLite (WAL), multi-tenant,
│                      merkle-диффинг журналов; тот же core::journal
└── ipc/             — unix socket (ctl), StatusNotifierItem (трей)
```

Ключевые решения (обоснование — RESEARCH.md):

1. **Язык — Rust.** Единственный стек, который закрывает «крошечный след» и имеет корректный ответ на всех целях: SCTK для layer-shell (в winit его нет и не будет — issue #2582), winit/x11rb для X11, и тот же winit-путь позже станет Windows/macOS (там hittest/on-top/transparency работают из коробки с 0.27/0.30.13).
2. **Рендер — softbuffer, без GPU.** Спрайт ≤128 px на 8–15 fps — CPU-блит с damage-регионами; idle-CPU ≈ 0, ни резидентного GL-контекста, ни ~100 МБ драйверной кучи. wgpu — только если позже захотим шейдерные эффекты.
3. **Оверлей по модели wl_shimeji** (доказавшей 0.9% CPU / 56 МиБ на 7 маскотов): один прозрачный layer-shell surface на выход (layer=overlay, `keyboard_interactivity: none`, exclusive_zone −1), питомцы — субповерхности; input region = прямоугольники под спрайтами, обновляется по кадру. Внимание: `wl_region` — только объединение прямоугольников, пиксельных масок на Wayland нет.
4. **Геометрия окон — плагинные «органы чувств»**, деградация штатная: нет провайдера → питомец просто не лезет на окна, всё остальное работает. Это отвязывает судьбу проекта от войн компоситоров.
5. **Отвергнутые стеки** (кратко; полные выкладки в RESEARCH.md): Godot — нет passthrough/on-top на Wayland по собственной документации + ~200 МБ резидентно; Qt — Shijima-Qt умер именно на этом пути с вердиктом автора «Qt was not the right framework»; GTK4 — нет keep-above на X11 и мёртв для Win/mac; Electron/Tauri — худший click-through на Linux + браузерный движок ради 128-px PNG; SDL3 — нет input-shaping на Wayland.

## 5. Формат пака (нативный)

```
mypet.driftpack/              # zip или каталог
├── pack.toml                 # id, имя, автор, ЛИЦЕНЗИЯ (обязательно), версия,
│                             # масштаб, fps по умолчанию
├── sheet.png                 # spritesheet (или frames/*.png)
└── anims.toml                # анимации: кадры, длительности, якоря, хитбоксы,
                              # маппинг на состояния behavior-машины
                              # (walk, run, sit, sleep, fall, land, drag, eat,
                              #  pet, climb_l/r, hang, sick, happy, …)
```

Минимальный обязательный набор состояний: `idle, walk, fall, drag` — остальное движок заменяет фолбэками. Валидатор пака — `driftling pack lint`.

## 6. Этапы (milestones)

| | Содержание | Критерий приёмки |
|---|---|---|
| **M0** «Ходит» | Wayland-оверлей (KDE+wlroots), один питомец из встроенного пака, ходьба/падение/сон по кромке экрана, drag с броском, клик-реакции, `ctl summon/dismiss`, автозапуск | На Plasma и sway: питомец живёт на экране, клики сквозь пустые места проходят, CPU в idle <0.5% |
| **M0.5** «Настройки-UI» | Окно настроек (eframe/egui): статус, призвать/убрать/стоп, параметры поведения и размер из `config.toml`, тумблер автозапуска; демон перечитывает конфиг по IPC `Reload` | Изменение скорости/размера применяется к живому питомцу без перезапуска демона |
| **M1** «Окна-рельеф» | worldsense: KWin + sway + Hyprland + X11-бэкенд оверлея с EWMH; ходьба по верхним кромкам окон, падение при их движении | На KDE Wayland и X11: питомец сидит на заголовке, падает при сворачивании окна |
| **M2** «Тамагочи» | Статы, кормление/меню, сон, рост яйцо→взрослый, оффлайн-пересчёт, персистентность **сразу журналом событий**, трей, статус-карточка | Питомца можно довести до взрослой формы; при недельном простое он «голодный, но живой» |
| **M3** «Один питомец везде» | driftling-server (бинарь+Docker), протокол push/pull+присутствие, режим «папки» для Syncthing/Nextcloud, lease/handoff с анимацией перехода, E2E-опция | Два устройства кормят питомца офлайн → после синка состояние идентично, без диалогов; питомец перебегает на активное устройство <5 с |
| **M4** «Контент» | Нативный формат пака, конвертер shimeji-паков, мультипитомцы, мультимонитор-полировка, GNOME-расширение | Импорт ≥90% выборки из 20 популярных паков shimejis.xyz без ручной правки |
| **M5** «Кроссплатформа» | Windows, затем macOS (worldsense: Win32 / Accessibility) | CI собирает три ОС; фичи M0–M3 работают на Windows |
| **M6** «Внутри окон» | Браузерное расширение + native messaging; tty-режим | Питомец «перепрыгивает» с рабочего стола на страницу в браузере |
| **M7** «Телефон и веб» | Android-клиент (оверлей/виджет), веб-«комната» из driftling-server, core на WASM; iOS следом | Покормить питомца с телефона и из браузера; присутствие переходит ПК↔телефон |

## 7. Нефункциональные требования

- **CPU**: <0.5% одного ядра при 1 питомце в движении; ≈0 в покое (сон/idle с редкими кадрами).
- **RAM**: <60 МБ RSS с одним паком (ориентир доказан wl_shimeji: 56 МиБ на 7 маскотов).
- **Без GPU-резидентности**, без wakeup'ов чаще частоты кадров текущей анимации; в покое — таймер ≥1 с.
- Старт демона <1 с; краш не теряет состояние питомца (журналируемая запись).
- Никаких сетевых обращений. Телеметрии нет.
- Локализация: en + ru с первого релиза (Fluent или gettext).
- Логи в journald (`--verbose` для отладки), понятная диагностика «почему деградированный режим» (`ctl doctor`).

## 8. Репозиторий

- Хостинг: GitHub, публичный с первого коммита. Имя: `driftling`.
- **Лицензии**: код — MIT OR Apache-2.0 (стандарт Rust-экосистемы, максимум переиспользования), **включая сервер** — несвободный сервер при свободном клиенте (модель Joplin Server) гарантированно порождает трения с сообществом; наша ставка обратная — простой открытый протокол, который можно реализовать независимо. Следствие: код GPL-проектов (wl_shimeji GPL-2.0, libshijima GPL-3.0) **не копируем** — только clean-room по документации/протоколам; их можно читать как справку об идеях, наши KWin/GNOME-скрипты пишем свои. Собственный арт — CC0 или CC-BY. Чужие паки не бандлим (юридическая модель всех выживших проектов: фан-паки живут вне репозитория, DMCA-риск — на хостерах паков).
- Структура: cargo workspace по схеме §4 + `assets/` (свой пак), `docs/` (это ТЗ, RESEARCH, ARCHITECTURE, PACKS.md — спека формата), `extension/` (GNOME), `browser/` (M5).
- CI (GitHub Actions): fmt + clippy + test; сборочные матрицы Linux (deb, AppImage), позже Windows/macOS. Интеграционные тесты core без дисплея; смоук-тест оверлея в headless-компоситоре (labwc/sway nested).
- Пакеты: **deb + AppImage** сначала; Flatpak — вторым эшелоном (Wayland-сокет пробрасывается, но: автозапуск только через Background-портал, KWin D-Bus — `--talk-name=org.kde.KWin`).
- Документы: README (гифка!), CONTRIBUTING, CODE_OF_CONDUCT, шаблоны issue, «pack author guide».

## 9. Чего НЕ делаем (анти-скоуп)

- Никаких LLM-компаньонов/чатов в ядре (рынок уже переполнен: clawd-on-desk, Agentic-Desktop-Pet) — максимум как сторонний плагин в будущем.
- Никакой экономики «работа/деньги/магазин» в v1 (VPet-путь; противоречит принципу «не игра, а питомец»).
- Не «раздражающий» питомец: хаос-режим а-ля Desktop Goose — возможная опция, никогда не дефолт.
- Не движок-для-всего: один жанр (спрайтовый питомец), не платформа плагинов на старте.

## 10. Риски

1. **GNOME** — нет layer-shell (mutter#973 закрыт отказом) и не будет: честно документируем деградацию, полный режим — только через наше Shell-расширение (обновлять под каждый мажор GNOME) или XWayland. Прецедент полноценной реализации внутри Shell — Gnomelets.
2. **Разнобой compositors** — worldsense-плагины придётся сопровождать; смягчение: null-провайдер как штатный режим, а не ошибка.
3. **Hyprland** — известны нарушения клиппинга wl_subsurface (из-за которых wl_shimeji его не поддерживает) и захват указателя layer-поверхностью при exclusive-клавиатуре; смягчение: не используем субповерхности «на глазок» — проверяем на Hyprland с M0, держим фолбэк «отдельная layer-поверхность на питомца».
4. **Совместимость shimeji-паков** — длинный хвост экзотических actions.xml; смягчение: конвертер офлайн + честный отчёт «что не сконвертировалось», цель 90%, не 100%.
5. **Балансировка тамагочи** — скорости деградации требуют живой обкатки; все константы в конфиге + телеметрии нет, значит собираем фидбек руками (issue-шаблон «баланс»).
6. **Товарные знаки** — суффикс «-gotchi» рядом с маркой Bandai: риск низкий (индюшные «-gotchi» сосуществуют публично), но перед релизом 1.0 перепроверить; запасное имя без суффикса заготовить.
7. **Рост журнала событий** — питомец живёт годами, журнал бесконечен; смягчение: периодические подписанные снапшоты-чекпоинты + компакция хвоста (эту домашку паттерн tonsky оставляет нерешённой — решаем сами, закладываем в формат журнала с M2).
8. **Кривые часы устройств** — HLC-guard ±60 с и кламп decay-математики (§3.5); guard надо конфигурировать самим, у библиотек он по умолчанию выключен.
9. **Общий хост: стоимость и злоупотребления** — кто платит за инстанс, rate limiting, квоты на журнал (данные крошечные, но абьюз возможен); старт — общий хост как «бета для своих», решение о публичном — после M3.
